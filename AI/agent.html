Agent 是什么 ​

智能体被定义为任何能够通过传感器（Sensors）感知其所处环境（Environment），并自主地通过执行器（Actuators）采取行动（Action）以达成特定目标的实体。

放到今天的大模型产品语境里：大模型擅长理解和生成文本，但默认只会「一问一答」。Agent（智能体） 指的是：在模型之上，再加一层能规划、调用工具、根据结果继续行动的运行时，让它朝目标持续推进，而不是只回一句漂亮话。

可以粗记成：

模型 = 脑子，Agent = 会用工具、会按步骤做事的执行者。

和普通聊天有什么区别 ​

普通对话（Chat）Agent
交互形态用户问 → 模型答，多半一轮结束用户给目标 → Agent 多步执行直到完成或失败
能否碰外部世界一般不能（除非产品内置了固定插件）可以读文件、跑命令、调 API、查库等
中间过程通常不可见或很少常有计划、工具调用、观察结果、再决策的循环
失败处理再问一句重试可按流程回退、换策略、请求确认

一句话：Chat 偏回答问题，Agent 偏完成任务。

Agent 常见构成 ​

不同产品叫法不一，但骨架往往类似：

  1. 目标 / 任务：用户要达成什么（修 bug、写周报、查天气再总结）
  2. 大脑（LLM）：理解意图、选下一步、组织最终回复
  3. 工具（Tools）：真正动手的能力——本地命令、浏览器、GitHub、内部 RPC 等
  4. 记忆 / 上下文：当前对话、打开的文件、历史工具结果、长期笔记等
  5. 编排循环（Loop）：思考 → 行动 → 观察 → 再思考，直到结束条件满足

最常见的一种循环叫 ReAct（Reason + Act）：先推理该做什么，再调用工具，再根据观察继续。

和 Skill、MCP 的关系 ​

在 Cursor、Claude Code 这类产品里，这三个词经常一起出现，职责不同：

概念一句话
Agent整套「能多步完成任务」的运行时 / 产品形态
Skill教 Agent 按什么流程做事（规范与步骤）
MCP给 Agent 接上外部工具与数据的标准协议

关系可以记成：

  • Agent 是谁在干活
  • Skill 是怎么干（流程）
  • MCP 是能干哪些外部的事（手脚）

更细的对比见：Skill 与 MCP 异同；Skill / MCP 专题见：Skill、MCP。

常见形态 ​

按使用方式粗分：

  • 对话式 Agent：在聊天窗里给目标，例如 Cursor Agent、Claude 的 Agent 模式
  • IDE 内嵌 Agent：和编辑器、终端、Git 深度结合，改代码并跑验证
  • 自主 / 后台 Agent：少交互、长时间跑任务（需更强权限与护栏）
  • 多 Agent：拆成「规划 / 编码 / 评审」等角色协作（工程更复杂，不是入门必选项）

入门阶段先掌握「单 Agent + 工具调用循环」足够。

能力边界与风险 ​

Agent 变强，风险也变大：

  • 权限过大：能删文件、推远程、调生产接口时，误操作代价高
  • 幻觉仍在：模型可能编造路径、命令或结论，需要验证步骤
  • 循环失控：反复无效重试，耗时耗钱；要有步数/超时上限
  • 上下文膨胀：工具结果塞太多，反而选错下一步

落地建议：

  • 危险操作要确认或走 Skill 里的硬约束
  • 关键任务固定「改完必须跑测试 / 检查清单」
  • 工具权限按最小必要原则开通（尤其是 MCP Server）

小结 ​

  • Agent = 模型 + 工具 + 多步编排，目标是完成任务而不只是聊天
  • 核心循环是：思考 → 行动 → 观察 → 再决策
  • 工程上用 Skill 管流程，用 MCP 管外部连接，两者都挂在 Agent 之上
