本页目录

AGENTS.md ​

AGENTS.md 是仓库根目录（也可以在子目录）里的一份 Markdown 说明书，写给各种编码 Agent 看：这个项目怎么跑、目录约定、不能碰什么。

它不是 Cursor 私有格式。Cursor、Codex、很多 Host 都会读。Claude Code 常用 CLAUDE.md，意思接近；一个仓库可以两份都放，内容别互相打架。

Rule 说明：Rule。和 Skill、MCP 对照：Skill、MCP、Rule 异同。

它干什么 ​

打开这个仓库时，Agent 把 AGENTS.md 当成项目公约带进上下文。你不用每聊一次都重复「用 pnpm、别跑 rm」。

适合写：

  • 安装 / 开发 / 测试命令
  • 目录地图（代码在哪、别改生成物）
  • 提交、分支、禁止事项
  • 「改到这个子包时要注意什么」（子目录再放一份）

不适合写：

  • 按场景才启用的长流程 → Skill
  • 只对 *.scss 生效的细规则 → Rule 的 glob
  • 调外部 API 的连接方式 → MCP

文件放哪 ​

text
repo/
├── AGENTS.md              # 整仓公约
├── CLAUDE.md              # 可选，给 Claude Code
├── apps/
│   └── web/
│       └── AGENTS.md      # 只在动这个子树时更相关
└── .cursor/rules/         # Cursor 的细规则，见 Rule

根目录一份就够起步。Monorepo 才在子包再放。

最小能用的内容 ​

md
# AGENTS.md

## 命令

- 安装：`pnpm i`
- 开发：`pnpm dev`
- 测试：`pnpm test`
- 不要用 `rm`，用 `trash`

## 目录

- 业务代码在 `src/`
- 不要手改 `dist/`、lockfile 里与本次无关的块

## 协作

- 没要求就不要提交
- 不要改 git config

写短、写命令、写禁区。Agent 已经会编程，不必在这里科普框架。

和 Rule、Skill 怎么分工 ​

AGENTS.mdRuleSkill
读者各种 Agent（偏可移植）主要是 Cursor各种支持 Skill 的 Host
形态仓库里一两份 Markdown.cursor/rules/*.mdc，可 globSKILL.md 目录
进上下文项目级，偏常驻常驻或按文件类型先目录，匹配后再读正文
适合「这个仓库怎么干活」「改这类文件时的短约束」「做这类任务的步骤」

同一条禁令不要复制三遍。仓库怎么跑放 AGENTS.md；Cursor 里按文件类型收紧放 Rule；评审 / 排障步骤放 Skill。
