shuohao-skills ​

shuohao-skills 是一套 AI 短剧制作的 Agent Skill 集合，把一本小说从头跑到可直接喂生成管线的制作素材：拆角色、排大纲、出场景与道具设定、写剧本、切分镜。给 AI 编码 Agent 用，Claude Code 和 Codex 都能跑。

整条管线 ​

五个 Skill 按流水线顺序协作，改编大纲收敛结构，剧本、场景、角色三者同步迭代，分镜只做输出不做新决定：

text
小说原文
  ↓
novel-outline      改编大纲（结构、爽点、分集梗概）
  ↓
novel-characters   角色设定集（画像、形象提示词、音色提示词）
novel-art          美术设定集（场景 + 叙事道具）
  ↓
novel-script       剧本（场次 + 节拍流、台词本）
  ↓
novel-storyboard   分镜（段 → 分镜 → 分镜图 → 投产包）
Skill做什么
novel-outline把一本小说改编成短剧大纲五件套：改编说明、人物表、爽点表、分集梗概、资产清单。14 道质量门全部脚本检查，支持已有大纲的体检模式
novel-characters把大纲定下的角色做成角色设定集：人物画像、形象提示词、音色提示词、角色设定图。吃 outline.json 预填角色表
novel-art给 AI 短剧出美术设定集（场景 + 叙事道具）：一致性锚点、光照与状态变体、尺度参照、无人无手白底提示词。11 道质量门全部脚本检查
novel-script写剧本：场次 + 节拍流（动作与台词交替），逐集时长按语速确定性折算，台词本按角色聚合带音色提示词直接对接 TTS。10 道质量门全部脚本检查
novel-storyboard出分镜：段（一次生成 ≤15 秒）→ 分镜（2–5 秒硬门）→ 分镜图，MiniMax H3 提示词对齐，export 一键出投产包。17 道质量门全部脚本检查

五个 Skill 的报告都支持中英双语界面：默认中文，render --lang en 出全英文报告。

安装 ​

bash
git clone https://github.com/eternityspring/shuohao-skills.git
cd shuohao-skills
./scripts/install.sh

脚本会自动检测本机装了 Claude Code 还是 Codex，把所有 Skill 软链过去——git pull 之后立刻生效，不用重装。

bash
./scripts/install.sh novel-characters   # 只装某一个
./scripts/install.sh --codex            # 只装到 codex
./scripts/install.sh --uninstall        # 取消软链

手动软链也可以（路径换成当前 Agent 的 skills 目录）：

bash
ln -s "$PWD/skills/novel-characters" ~/.claude/skills/novel-characters

前置条件 ​

必需？说明
Node≥ 18。Skill 脚本只用标准库，没有 npm 依赖
模型额度用当前会话的额度，不需要任何 API key
codex CLI可选。出图才用得上（走内置 $imagegen），没有就跳过出图，其余产出照常

工作目录约定 ​

从头跑完五段，按 Skill 各建一个目录归档：

text
<demo>/
├── outline/       ← novel-outline 产出
├── characters/    ← novel-characters 产出
├── art/           ← novel-art 产出
├── script/        ← novel-script 产出
├── storyboard/    ← novel-storyboard 产出 + export 投产包
│   ├── manifest.json
│   ├── E01-01/    ← 每段一个文件夹（prompt.md + f1..fN.png）
│   └── …
├── docs/
└── scripts/

要点：

  • 每个 Skill 一个目录，装自己的 json / md / html 三件套
  • 分镜的 manifest.json 与 E01-0x/ 投产包一起归 storyboard/
  • 段文件夹不要再往下收一层——报告 HTML 与段文件夹必须同级，多套一层目录，报告里的图会静默全变成「未生成」占位

合成单页报告 ​

五段的报告可以合成一张单页，左侧导航切换——有哪几段就出哪几个面板：

bash
node scripts/report.mjs --from <demo目录> --out report.html

它是组装器，不是独立 Skill：调各自的 render --html 拿产物再拼装，五个 Skill 各自仍然独立可跑。

怎么用 ​

安装后，在 Agent 对话里直接说意图即可触发对应 Skill，例如：

  • 「把这本小说改编成 60 集短剧大纲」→ novel-outline
  • 「根据 outline.json 出角色设定集」→ novel-characters
  • 「写第 3 集剧本」→ novel-script
  • 「给第 1 集出分镜并 export 投产包」→ novel-storyboard

出图说明：大纲、剧本、分镜文案等全流程 Agent 都能跑；novel-art / novel-storyboard 的设定图、分镜图需要 Codex CLI（内置 $imagegen）或把提示词复制到 Midjourney / 即梦等外部平台。没有出图能力也不影响 json / md / html 报告产出。

每个 Skill 目录结构自包含，可以单独拷走：

text
skills/<skill-name>/
├── SKILL.md          给 Agent 读的工作流（必需）
├── README.md         给人读的说明
├── scripts/
│   ├── <name>.mjs    确定性工具，零依赖
│   └── selftest.mjs  自测，不调模型（必需）
├── references/       按需加载的详细指令
├── examples/         自带样例
└── assets/           截图

质量门 ​

每个 Skill 都有脚本化的质量门，不调用模型、不花额度，本地跑自测：

bash
for f in skills/*/scripts/selftest.mjs; do node "$f"; done

质量门覆盖角色分档上限、爽点间隔、分镜时长硬门、提示词对齐等对账等——不靠模型自觉。
