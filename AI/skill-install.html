npx skills add 是怎么安装 Skill 的 ​

社区里常见这种安装方式：

bash
npx skills add freestylefly/awesome-gpt-image-2 --global --all --copy

它不是把 Skill 装进 node_modules，也不会起一个插件进程。电脑实际做的事就 7 步：npx 从 npm 下载安装程序 → 程序去 GitHub clone 仓库 → 找到 SKILL.md → 拷到 Cursor 等会扫描的目录。逐步拆解见下面「实际调用链」。

Skill 是什么、装完之后怎么进上下文，见：Skill 说明、Skill 生效原理。本文只讲安装器本身。

上面这条来自 awesome-gpt-image-2 的 README，含义是「装到本机所有支持的 Agent」。

先拆命令 ​

片段作用
npx skills不全局安装 CLI，临时跑 npm 包 skills
add owner/repoGitHub 简写，等价于 https://github.com/freestylefly/awesome-gpt-image-2
--global / -g装到用户目录，所有项目都能用
--all仓库里所有 Skill → 本机所有已检测到的 Agent，并跳过交互
--copy每个 Agent 目录写一份真实文件，不建符号链接

只给 Cursor 装、且只要这一个技能，可以写成：

bash
npx skills add freestylefly/awesome-gpt-image-2 \
  --skill gpt-image-2-style-library \
  --agent cursor --global --yes --copy

add 还接受完整 GitHub / GitLab URL、git@...、本地路径、直接指向某个 SKILL.md 的 tree 地址。

实际调用链（这条命令电脑在干什么） ​

就两样东西：

名字人话
npxNode 自带的「临时跑一个 npm 包」工具。你电脑上可以没有安装过 skills，它会先去网上把包下载下来再跑。
skills 包Vercel 放到 npm 上的安装程序。包名就叫 skills，源码在 vercel-labs/skills。

这条命令电脑实际走的步骤：

text
1. 你敲：
   npx skills add freestylefly/awesome-gpt-image-2 --global --all --copy

2. npx 去 npm 官网（registry.npmjs.org）找一个名叫 skills 的包
   下载下来，执行里面的程序：bin/cli.mjs

3. 这个程序读你后面的字：
   add     → 要安装
   freestylefly/awesome-gpt-image-2  → GitHub 用户/仓库名
   --global --all --copy             → 装哪、装几个、怎么拷

4. 程序把 owner/repo 拼成 GitHub 地址：
   https://github.com/freestylefly/awesome-gpt-image-2
   然后 git clone 整仓下来（拷到一个临时文件夹）

5. 在仓库里找带 SKILL.md 的文件夹
   这个仓找到的是：
   agents/skills/gpt-image-2-style-library/

6. 按参数把这个文件夹写到本机：
   --global → 写到你家目录，不是当前项目
   --all    → Cursor / Claude / Codex……本机有哪个就装哪个
   --copy   → 真拷文件，不建快捷方式（符号链接）

7. 装完了。Cursor 下次开会话，去 ~/.cursor/skills/ 扫到这份 SKILL.md

对应到源码也就是两步：npx 启动 cli.ts → add 子命令里 cloneRepo()，再 discoverSkills()。

原理：写一次，分发到各 Host ​

各产品扫的路径不一样：Cursor 看 ~/.cursor/skills/，Claude Code 看 ~/.claude/skills/，Codex 看 ~/.codex/skills/……Skill 本身只是带 YAML 头的 SKILL.md（Agent Skills 规范）。

npx skills add 做的是：clone 仓库 → 发现 Skill → 按产品目录落地。

对这个仓库，发现路径是现成的：

text
agents/skills/gpt-image-2-style-library/SKILL.md

CLI 会在仓库里找这些位置（浅层递归，最多约 3 层）：根目录、skills/、.agents/skills/、.claude/skills/，以及 .claude-plugin/marketplace.json 声明的路径。找不到再全库搜。这个项目还带 Claude Code 插件清单，所以 npx skills add 和 /plugin marketplace add 都能找到同一份 Skill。

检测「本机装了哪些 Agent」很朴素：看有没有对应配置目录。例如存在 ~/.cursor 就算 Cursor 已安装。

三个参数各自解决什么 ​

--global：跨项目，不污染当前仓库 ​

范围标志Cursor 落地
项目（默认）无./.agents/skills/（可进 git，给团队）
本机全局-g~/.cursor/skills/

风格库、出图协议这类能力跟具体业务仓库无关，适合全局。装完后任意项目开 Cursor 都能扫到。

规范目录（canonical）在全局时是 ~/.agents/skills/。Cursor 全局路径是 ~/.cursor/skills/，项目路径走通用的 .agents/skills/。

--all：跳过「选哪个 Skill、装给哪个 Agent」 ​

--all 约等于 --skill '*' --agent '*' -y。

不加时会交互：选 Skill、选 Agent（或只装本机检测到的）。--all 表示：仓库里发现的全装，本机有 ~/.cursor、~/.claude、~/.codex 等就全写一份。

这个仓库目前主要是一个技能：gpt-image-2-style-library。--all 的价值更在「多 Agent」，不在「很多 Skill」。

--copy：每份独立文件，不依赖 symlink ​

默认（推荐、好更新）是：

  1. 拷一份到规范目录：~/.agents/skills/gpt-image-2-style-library/
  2. 在 ~/.cursor/skills/...、~/.claude/skills/... 建相对路径符号链接指向那一份
  3. symlink 失败再退回 copy

--copy 跳过规范目录那一步，直接把目录复制到每个 Agent 路径。好处：

  • Windows / 部分沙箱对 symlink 不友好
  • 有的 Host 不跟随符号链接
  • 改某一端的 Skill 不会改到另一端

代价：多份拷贝，npx skills update 要各写一遍，磁盘也更大。这个 Skill 还带 references/、assets/、bin/，copy 会整目录复制。

仓库推荐 --copy，是为了「装完就能用、少踩 symlink」。只给自己用、且更新频繁，可以去掉 --copy，用默认 symlink。

装完之后怎么生效 ​

安装只是把文件放到磁盘。Cursor / Claude Code 启动时扫描约定目录，不会把整份 SKILL.md 立刻塞进模型。

  1. L1：只注入 name + description（每个大约一百来个 token）
  2. L2：用户说「用风格库出一张信息图」或打 /gpt-image-2-style-library 时，才读完整 SKILL.md
  3. L3：正文里点到 references/ 再打开，点到 bin/ 再执行

所以：装了 ≠ 每条消息都带着整份案例库。description 写清楚，Agent 才会去打开它。装完后新开一轮会话更稳妥。完整加载机制见：Skill 生效原理。

和「npm 装包」的差别 ​

npx skills addnpm i -g gpt-image-2-style-library
产物各 Agent 的 skills/ 目录全局 npm 包 + 该包自己的 install
消费者Cursor / Claude / Codex …还要再跑 gpt-image-2-style-library install all
本质分发 Markdown 协议分发 Node CLI

同一仓库两条路：npx skills add 是跨 Agent 的标准分发；npm 包是他们自己的同步脚本，主要写 ~/.codex/skills、~/.claude/skills、~/.agents/skills。

装完怎么查、怎么更新 ​

bash
npx skills list -g          # 看全局装了什么
npx skills list -a cursor
npx skills update -g        # 拉仓库最新再覆盖
npx skills remove --global gpt-image-2-style-library

Cursor 侧应能看到：~/.cursor/skills/gpt-image-2-style-library/SKILL.md（--copy 时是实体目录）。

一句话 ​

npx 负责跑安装器，owner/repo 负责定位源，--global 决定写到家目录，--all 决定全 Skill × 全 Agent 且不提问，--copy 决定用复制而不是链接。 装完之后仍是普通 Skill：被扫描到、被 description 选中、再读进上下文。
