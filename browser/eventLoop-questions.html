事件循环经典面试题 ​

两道题分别考察：变量提升 / 闭包 + 宏微任务，以及 Node.js 中 process.nextTick 与 Promise / setTimeout 的优先级。

题一：闭包 + 宏微任务 ​

一道题同时考察：变量提升、作用域与闭包、宏任务 / 微任务、后置递增 a++。

题目 ​

js
var a = 1;

function foo() {
  console.log(a);

  var a = 2;

  Promise.resolve().then(() => {
    console.log(a);
  });

  setTimeout(() => {
    console.log(a);
  }, 0);

  return function () {
    console.log(a++);
  };
}

const bar = foo();

console.log(a);

bar();
bar();

a = 10;

console.log(a);

setTimeout(() => {
  console.log(a);
}, 0);

Promise.resolve().then(() => {
  console.log(a++);
});

最终输出 ​

undefined
1
2
3
10
4
10
4
11

逐步解析 ​

1. 同步代码：foo() 内部 ​

foo 里有 var a = 2，函数作用域内会发生变量提升，等价于：

js
function foo() {
  var a;              // 提升到函数顶部，此时 a === undefined
  console.log(a);   // undefined
  a = 2;
  // ...
}

这里的 a 是 函数内部的 a，和外层全局的 var a = 1 不是同一个变量。因此第一行输出 undefined，而不是 1。

同时，foo 注册了：

  • 一个 微任务（Promise.then）
  • 一个 宏任务（setTimeout）

两者回调都通过闭包引用 foo 内部的 a，不会读到全局的 a。

2. 同步代码：全局 ​

代码输出原因
console.log(a)1访问的是全局 a，foo 内部的 a 与之无关
bar()2bar 闭包引用 foo 内的 a（当前为 2），a++ 先打印再自增
bar()3同上，foo 内的 a 已被加到 3
a = 10—修改的是全局 a，闭包里的 a 仍是 4
console.log(a)10全局 a

关于 a++：console.log(a++) 等价于「先取当前值打印，再 +1」。两次 bar() 后，foo 内部的 a 从 2 → 3 → 4。

3. 微任务（全部同步代码执行完后） ​

微任务按注册顺序依次清空：

顺序来源输出原因
1foo 里的 Promise.then4闭包引用 foo 内的 a，此时已是 4（被 bar() 改过）
2全局的 Promise.then10访问全局 a，值为 10；a++ 后全局 a 变为 11

易错点

很多人以为 foo 里注册的微任务会输出 2，因为它在 a = 2 之后立刻注册。但微任务要等整段同步代码跑完才执行，那时 bar() 已经把闭包里的 a 加到了 4。

4. 宏任务（微任务清空后再执行） ​

宏任务同样按注册顺序依次执行：

顺序来源输出原因
1foo 里的 setTimeout4闭包，foo 内的 a 仍为 4
2全局的 setTimeout11全局 a，微任务里已自增为 11

执行流程图 ​

同步阶段
├── foo(): undefined
├── 全局: 1
├── bar(): 2
├── bar(): 3
└── 全局: 10

微任务队列（FIFO）
├── foo 的 Promise → 4
└── 全局 Promise → 10（全局 a 变为 11）

宏任务队列（FIFO）
├── foo 的 setTimeout → 4
└── 全局 setTimeout → 11

考点总结 ​

  1. var 变量提升：函数内 var a 会遮蔽外层同名变量，提升后初始值为 undefined。
  2. 作用域隔离：全局 a 与 foo 内的 a 是两个绑定；a = 10 只改全局，不影响闭包。
  3. 闭包共享绑定：bar 和 foo 内的 Promise / setTimeout 回调，引用的是同一个 foo 内的 a。
  4. 微任务优先于宏任务：所有微任务清空后，才执行宏任务。
  5. 同类型任务 FIFO：多个 Promise.then 按注册顺序执行；多个 setTimeout(0) 同理。

题二：Node.js nextTick + Promise + setTimeout ​

考察 Node.js 事件循环里三类异步的优先级：process.nextTick > Promise 微任务 > setTimeout 宏任务，以及每个宏任务结束后如何穿插 nextTick / 微任务。

题目 ​

js
console.log(1);
setTimeout(() => {
  console.log(2);
  new Promise((resolve) => {
    console.log(4);
    resolve();
  }).then(() => {
    console.log(5);
  });
  process.nextTick(() => {
    console.log(3);
  });
});
new Promise((resolve) => {
  console.log(7);
  resolve();
}).then(() => {
  console.log(8);
});
process.nextTick(() => {
  console.log(6);
});
setTimeout(() => {
  console.log(9);
  process.nextTick(() => {
    console.log(10);
  });
  new Promise((resolve) => {
    console.log(11);
    resolve();
  }).then(() => {
    console.log(12);
  });
});

最终输出 ​

1
7
6
8
2
4
3
5
9
11
10
12

逐步解析 ​

Node 里记住这条优先级链：

同步代码
  → process.nextTick 队列（全部清空）
  → Promise 微任务队列（全部清空）
  → 取一个宏任务（如 setTimeout）
  → 该宏任务里的同步代码
  → 再清空 nextTick → 再清空微任务
  → 下一个宏任务 …

1. 同步阶段 ​

代码输出 / 效果
console.log(1)1
第一个 setTimeout注册宏任务 A
new Promise 执行器7（同步），并注册 .then → 8
process.nextTick注册 nextTick → 6
第二个 setTimeout注册宏任务 B

同步结束，输出：1 7

2. 同步结束后的 nextTick / 微任务 ​

顺序队列输出
1nextTick6
2Promise 微任务8

易错点

浏览器没有 process.nextTick。在 Node 中 nextTick 优先于 Promise.then，所以是 6 再 8，不是反过来。

3. 宏任务 A（第一个 setTimeout） ​

回调内同步执行：2 → Promise 执行器 4（注册 then→5）→ 注册 nextTick→3。

该宏任务回调结束后：

顺序队列输出
1nextTick3
2Promise 微任务5

所以这一段是：2 4 3 5

即使代码里先写了 .then、后写 nextTick，执行时仍是 nextTick 先于 then。

4. 宏任务 B（第二个 setTimeout） ​

同理：同步 9 → 注册 nextTick→10 → Promise 执行器 11（注册 then→12）。

回调结束后：nextTick 10 → 微任务 12。

所以这一段是：9 11 10 12

执行流程图 ​

同步阶段
├── 1
├── 注册 setTimeout A
├── 7（Promise 执行器）+ 注册 then→8
├── 注册 nextTick→6
└── 注册 setTimeout B

同步后清空
├── nextTick → 6
└── 微任务 → 8

宏任务 A
├── 同步: 2, 4（注册 then→5、nextTick→3）
├── nextTick → 3
└── 微任务 → 5

宏任务 B
├── 同步: 9, 11（注册 nextTick→10、then→12）
├── nextTick → 10
└── 微任务 → 12

考点总结 ​

  1. process.nextTick 不是宏任务：它挂在当前阶段之后、微任务之前，优先级高于 Promise.then。
  2. 每个宏任务结束后都会先清空 nextTick，再清空微任务，再进入下一个宏任务。
  3. Promise 构造函数是同步的：new Promise((resolve) => { console.log(...) }) 里的 log 立刻执行；只有 .then 才是微任务。
  4. 两个 setTimeout 按注册顺序进入 timers 队列，FIFO；中间穿插各自产生的 nextTick / 微任务。
