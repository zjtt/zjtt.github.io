TCP 建立连接和断开连接的详细流程 ​

TCP（传输控制协议）是一种面向连接的、可靠的传输层协议，其建立连接和断开连接都有严谨的流程。下文默认由客户端主动发起连接与关闭。

TCP 建立连接（三次握手） ​

流程图 ​

mermaid
sequenceDiagram
    participant C as 客户端
    participant S as 服务器

    Note over S: LISTEN
    C->>S: ① SYN seq=x
    Note over C: SYN_SENT
    S->>C: ② SYN+ACK seq=y, ack=x+1
    Note over S: SYN_RCVD
    C->>S: ③ ACK seq=x+1, ack=y+1
    Note over C,S: ESTABLISHED

为什么需要三次握手 ​

  1. 双方都确认自己的发送、对方的接收能力：两次只能确认「我能发、你能收」中的一部分；第三次握手让服务器也确认「客户端能收到我的包」。
  2. 同步双方初始序列号（ISN）：后续可靠传输、重传、有序交付都依赖这个起点。
  3. 防止历史重复 SYN 误建连接：网络中可能残留旧的 SYN。若只用两次握手，服务器一收到旧 SYN 就进入就绪，可能白白占用资源；第三次握手要求客户端再确认一次，旧连接无法完成，会被丢弃。

详细步骤 ​

  1. 准备阶段

    • 服务器处于 LISTEN，等待连接。
    • 客户端从 CLOSED 准备发起连接。

  2. 第一次握手（客户端发 SYN）

    • 客户端发送 SYN 报文，携带随机初始序列号 seq=x。
    • 客户端进入 SYN_SENT。

  3. 第二次握手（服务器回 SYN + ACK）

    • 服务器回复 SYN + ACK：自身初始序列号 seq=y，确认号 ack=x+1。
    • 服务器进入 SYN_RCVD。

  4. 第三次握手（客户端发 ACK）

    • 客户端发送 ACK：seq=x+1，ack=y+1（该 ACK 也可以捎带数据）。
    • 客户端进入 ESTABLISHED；服务器收到后也进入 ESTABLISHED，连接建立完成。

TCP 断开连接（四次挥手） ​

流程图 ​

sequenceDiagram

    participant S as 服务器

    Note over C,S: ESTABLISHED
    C->>S: ① FIN seq=u
    Note over C: FIN_WAIT_1
    S->>C: ② ACK ack=u+1
    Note over S: CLOSE_WAIT
    Note over C: FIN_WAIT_2
    Note right of S: 半关闭：服务端仍可发送剩余数据
    S->>C: ③ FIN seq=w, ack=u+1
    Note over S: LAST_ACK
    C->>S: ④ ACK ack=w+1
    Note over C: TIME_WAIT（约 2MSL）
    Note over S: CLOSED
    Note over C: CLOSED

为什么是四次挥手 ​

TCP 是全双工的：每个方向各自独立关闭。

  • 客户端发 FIN，只表示「我这边不再发数据了」，但还可以继续收。
  • 服务器先 ACK 确认收到 FIN（进入 CLOSE_WAIT），此时它可能还有数据要发，所以不能马上也 FIN。
  • 等服务器发完剩余数据后再发自己的 FIN，客户端再 ACK。于是常见是 4 次。

若服务器收到 FIN 后立刻也没有数据要发，可以把第 ② 步的 ACK 和第 ③ 步的 FIN 合并成一个报文，关闭过程就会变成「三次挥手」。

详细步骤 ​

  1. 第一次挥手（客户端发 FIN）

    • 客户端发送 FIN，seq=u，表示本端发送完毕。
    • 客户端进入 FIN_WAIT_1。

  2. 第二次挥手（服务器回 ACK）

    • 服务器回复 ACK，ack=u+1，seq=v。
    • 服务器进入 CLOSE_WAIT；客户端收到后进入 FIN_WAIT_2。
    • 此时是半关闭：客户端→服务器方向已关，服务器→客户端仍可传数据。

  3. 第三次挥手（服务器发 FIN）

    • 服务器发完剩余数据后发送 FIN，seq=w，ack=u+1。
    • 服务器进入 LAST_ACK。

  4. 第四次挥手（客户端回 ACK）

    • 客户端发送 ACK，ack=w+1，seq=u+1，并进入 TIME_WAIT。
    • 服务器收到 ACK 后进入 CLOSED。
    • 客户端在 TIME_WAIT 停留约 2MSL（MSL：最长报文段寿命）后进入 CLOSED。

TIME_WAIT 的作用 ​

主动关闭方进入 TIME_WAIT，主要是为了：

  1. 保证最后的 ACK 能送达：若 ACK 丢失，对端会重传 FIN，本端仍在 TIME_WAIT，可以再次回复 ACK。
  2. 让旧连接的延迟报文在网络中消亡：避免新连接（相同四元组）被旧包干扰。

因此会出现「端口短暂占用 / Address already in use」一类现象；不要轻易把 TIME_WAIT 改得过短。

异常断开：RST ​

正常关闭走 FIN 四次挥手。下列情况常见 RST（Reset），连接被立即复位，没有完整挥手：

  • 对端端口未监听、连接不存在
  • 进程崩溃或调用强制中止（如 abort）
  • 收到不符合当前状态的报文

RST 表示「连接立刻作废」，不保证对端还有数据可读完。

和 HTTP 的关系 ​

浏览器访问网页时，DNS 拿到 IP 后会先建立 TCP 连接，HTTP 请求跑在已 ESTABLISHED 的连接上。HTTP/1.1 Keep-Alive、HTTP/2 多路复用，都是为了少做握手/挥手，降低建连开销。
