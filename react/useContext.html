useContext 更新后，哪些组件会 re-render？ ​

面试题 ​

父组件通过 Context.Provider 向下传递值，其中两个子组件用 useContext 消费这个值。当 Provider 的 value 更新后，是只有这两个子组件会更新，还是所有子组件都会更新？

简短结论 ​

场景结果
只谈 Context 机制只有消费了该 Context 的组件会因其 value 变化而 re-render
实际常见写法（state 在 Provider 父组件里）所有子组件都会 re-render，因为父组件 state 变了，父组件本身会 re-render，默认会带着所有子组件一起渲染
做了优化后未消费 Context 的子组件可以用 React.memo 跳过无效渲染

一句话：Context 只「通知」订阅者，但父组件 re-render 会默认带动全部子组件。

示例代码 ​

tsx
import { createContext, useContext, useState, memo } from 'react'

const CountContext = createContext(0)

function ChildA() {
  const count = useContext(CountContext)
  console.log('ChildA render')
  return <div>A: {count}</div>
}

function ChildB() {
  const count = useContext(CountContext)
  console.log('ChildB render')
  return <div>B: {count}</div>
}

function ChildC() {
  console.log('ChildC render')
  return <div>C: 不消费 Context</div>
}

const MemoChildC = memo(ChildC)

export default function Parent() {
  const [count, setCount] = useState(0)

  return (
    <CountContext.Provider value={count}>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      <ChildA />
      <ChildB />
      <ChildC />
      {/* <MemoChildC /> 换成 memo 版本对比 */}
    </CountContext.Provider>
  )
}

点击按钮后，控制台通常输出：

Parent render
ChildA render
ChildB render
ChildC render   // 也渲染了，但不是 Context「点名」它，而是 Parent re-render 的连带结果

把 ChildC 换成 MemoChildC 后，再点击按钮，ChildC 不会再打印——props 没变，memo 拦住了。

原理解释 ​

1. Context 的订阅粒度 ​

React 在内部维护 Context 的订阅关系：只有调用了 useContext(CountContext)（或 <CountContext.Consumer>）的组件，才会在该 Context 的 value 引用变化时被标记为需要更新。

未订阅 Context 的兄弟组件，不会因为 Context value 单独变化而被 React 额外标记。

2. 为什么 ChildC 还是经常 re-render？ ​

常见写法里，useState 和 Provider 写在同一个父组件：

tsx
function Parent() {
  const [count, setCount] = useState(0)
  return (
    <CountContext.Provider value={count}>
      <ChildA />
      <ChildB />
      <ChildC />
    </CountContext.Provider>
  )
}

setCount → Parent re-render → React 默认继续渲染 Parent 返回的子树 → 所有子组件都会走一遍 render，不管用没用 Context。

所以面试里要分两层答：

  • 机制层：Context 变更 → 只触发 consumer 更新。
  • 实践层：Provider 父组件 re-render → 默认所有子组件都 render。

3. value 是对象时要注意引用 ​

tsx
// 每次 Parent render 都会生成新对象，即使 theme 没变，consumer 也会 re-render
<ThemeContext.Provider value={{ theme, toggle }}>

Provider 的 value 用 Object.is 比较。每次 render 新建对象 = 引用变了 = 所有 consumer 都会 re-render。

优化：

tsx
const value = useMemo(() => ({ theme, toggle }), [theme, toggle])
return <ThemeContext.Provider value={value}>...</ThemeContext.Provider>

常见优化手段 ​

  1. React.memo：未消费 Context 的子组件包一层，避免父组件 re-render 的连带渲染。
  2. 状态下沉 / 组件拆分：把 useState 抽到只包裹必要子树的子组件里，缩小 re-render 范围。
  3. 拆分 Context：把「常变的 count」和「几乎不变的 theme」拆成两个 Context，避免无关 consumer 被牵连。
  4. useMemo 稳定 value：value 是对象/数组时，避免无意义的引用变化。

对比：如果只更新 Context、Parent 本身不 re-render？ ​

把 state 提到外层，或用 ref + 强制刷新等模式，让 Provider 的 value 变而 Provider 组件不 re-render——这种场景下，确实只有 useContext 的那两个子组件会更新。但这不是日常项目里最主流的写法，面试答完机制后补一句即可。

面试口述模板 ​

Context value 变化时，React 只会通知订阅了这个 Context 的组件，也就是用了 useContext 的那两个子组件。

但实际开发里，state 往往在 Provider 的父组件里，setState 会导致父组件 re-render，默认所有子组件都会跟着 render 一遍，包括没用 Context 的 ChildC。

如果 ChildC 用 React.memo 包起来且 props 没变，就可以跳过这次渲染。另外 Provider 的 value 如果是对象，要记得 useMemo，不然每次父组件 render 都会让 consumer 无效更新。
