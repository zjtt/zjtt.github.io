vue3 dom-diff ​

来源 ​

作者：zero_one_
链接：Vue3 diff算法详解
来源：稀土掘金

Vue3 不会对所有节点做 diff。会走 patchKeyedChildren 的主要是：

  • v-for 容器节点
  • 手写 render() 产出的 children

无 key 的 v-for 会打上 UNKEYED_FRAGMENT，走全量按序替换，更慢。

Vue3 没有主动开放 Fragment API，但下面写法会生成片段：

  • 多根节点组件 → STABLE_FRAGMENT
  • v-for → Fragment
  • v-if 多个子节点、或不是单个文本节点 → STABLE_FRAGMENT

template 场景下，更新更多走 Block 的动态节点自更新，不一定进完整 diff。

Diff 更新 ​

入口是 patchKeyedChildren。c1 / c2 是新旧 children，i 是从头同步的指针，e1 / e2 是尾指针。

js
let i = 0
const l2 = c2.length
let e1 = c1.length - 1 // prev ending index
let e2 = l2 - 1        // next ending index

patch() 负责更新节点。isSameVNodeType() 要求 type 相同且 key 相同 才算同一节点（组件 type 是配置对象，元素 type 是标签标记）。

整体分三步：

  1. 从头对比，相同就 patch，不同就停下
  2. 从尾对比，相同就 patch，不同就停下
  3. 中间剩余节点：新增 / 删除 / 乱序移动
mermaid
flowchart TD
  A[sync from start] --> B[sync from end]
  B --> C{剩余节点?}
  C -->|i > e1 且 i <= e2| D[只新增: mount]
  C -->|i > e2 且 i <= e1| E[只删除: unmount]
  C -->|i <= e1 且 i <= e2| F[乱序: key map + LIS + move]

1. 对比头部 ​

js
// 1. sync from start
// (a b) c
// (a b) d e
while (i <= e1 && i <= e2) {
  const n1 = c1[i]
  const n2 = c2[i]
  if (isSameVNodeType(n1, n2)) {
    patch(n1, n2)
  } else {
    break
  }
  i++
}

注释中的例子：新旧队列从头部开始对齐。

2. 对比尾部 ​

尾部用 e1 / e2 各自回退。

js
// 2. sync from end
// a (b c)
// d e (b c)
while (i <= e1 && i <= e2) {
  const n1 = c1[e1]
  const n2 = c2[e2]
  if (isSameVNodeType(n1, n2)) {
    patch(n1, n2)
  } else {
    break
  }
  e1--
  e2--
}

当前指针指向节点相同，可复用，直接更新，尾指针一起前移：

再前移一次仍相同，继续更新：

指针指向不再相同，尾部对比停止。

前两步之后，中间只剩三种可能：

  • 只有新增：i > e1 且 i <= e2
  • 只有删除：i > e2 且 i <= e1
  • 乱序（一定有移动，可能夹杂增删）：i <= e1 且 i <= e2

3.3 乱序：尽量少动 DOM ​

目标不是求最小编辑距离（多数情况下更贵），而是求 旧节点下标的最长递增子序列，只移动不在这条稳定序列上的节点。

3.3.1 新节点 key → 下标 ​

js
const s1 = i
const s2 = i
const keyToNewIndexMap = new Map()

for (i = s2; i <= e2; i++) {
  const nextChild = c2[i]
  if (nextChild.key != null) {
    keyToNewIndexMap.set(nextChild.key, i)
  }
}

3.3.2 卸掉消失的旧节点，patch 可复用节点 ​

newIndexToOldIndexMap：新乱序区间（以 s2 为 0）→ 旧下标。旧下标会 +1 再存，因为 0 表示这个新节点没有对应旧节点。

js
let patched = 0
const toBePatched = e2 - s2 + 1
let moved = false
let maxNewIndexSoFar = 0
const newIndexToOldIndexMap = new Array(toBePatched)
for (i = 0; i < toBePatched; i++) newIndexToOldIndexMap[i] = 0

举个例子，两端 a b / f g 已同步完，中间剩余旧 c d e、新 e d c h：

节点 e 先写入（旧下标 3，存 4）：

js
newIndexToOldIndexMap = [4, 0, 0, 0]

全部写完后：

js
newIndexToOldIndexMap = [4, 3, 2, 0]

maxNewIndexSoFar 记录目前见到的最大新下标。只要每次 newIndex 都递增，说明相对顺序没乱，不用 move；一旦 newIndex < maxNewIndexSoFar，说明发生交叉，moved = true。

js
if (newIndex >= maxNewIndexSoFar) {
  maxNewIndexSoFar = newIndex
} else {
  moved = true
}

例如先碰到 c 的 newIndex = 4，再碰到 d 的 newIndex = 3，后者更小，至少要移动其中一个。

遍历旧乱序区间 s1 ~ e1：

js
for (i = s1; i <= e1; i++) {
  const prevChild = c1[i]

  // 新节点都 patch 完了，剩下的旧节点只能卸
  if (patched >= toBePatched) {
    unmount(prevChild)
    continue
  }

  let newIndex
  if (prevChild.key != null) {
    newIndex = keyToNewIndexMap.get(prevChild.key)
  } else {
    for (j = s2; j <= e2; j++) {
      if (
        newIndexToOldIndexMap[j - s2] === 0 &&
        isSameVNodeType(prevChild, c2[j])
      ) {
        newIndex = j
        break
      }
    }
  }

  if (newIndex === undefined) {
    unmount(prevChild)
  } else {
    newIndexToOldIndexMap[newIndex - s2] = i + 1
    if (newIndex >= maxNewIndexSoFar) {
      maxNewIndexSoFar = newIndex
    } else {
      moved = true
    }
    patch(prevChild, c2[newIndex])
    patched++
  }
}

无 key 时，newIndexToOldIndexMap[j - s2] === 0 用来避免同一个新节点被复用两次。这里已经 patch 完，后面只需要 move。

3.3.3 处理新增节点与移动节点 ​

moved === true 时，对 newIndexToOldIndexMap 求最长递增子序列。返回值是 map 里的下标，不是旧节点真实下标。

js
const increasingNewIndexSequence = moved
  ? getSequence(newIndexToOldIndexMap)
  : EMPTY_ARR

这个序列用来在最少次数下移动节点。newIndexToOldIndexMap 的下标本身就是乱序新节点的顺序，值是对应旧节点下标（+1）。若旧下标也呈递增，就只动那些不递增的节点。递增子序列越长，要移动的节点越少。比如下图：

c / d 前后都保持递增，只需移动 e、创建 h。

js
newIndexToOldIndexMap = [4, 2, 3, 0]
// e→旧3(+1=4), c→旧1(+1=2), d→旧2(+1=3), h 新增
increasingNewIndexSequence = [1, 2]  // 对应 c、d 在 map 中的下标，不是真实旧下标

从后往前遍历，才能用「已经处理过的后一个节点」当 insertBefore 锚点：

js
j = increasingNewIndexSequence.length - 1

for (i = toBePatched - 1; i >= 0; i--) {
  const nextIndex = s2 + i
  const nextChild = c2[nextIndex]
  const anchor = nextIndex + 1 < l2 ? c2[nextIndex + 1].el : parentAnchor

  if (newIndexToOldIndexMap[i] === 0) {
    patch(null, nextChild, container, anchor)
  } else if (moved) {
    if (j < 0 || i !== increasingNewIndexSequence[j]) {
      move(nextChild, container, anchor)
    } else {
      j--
    }
  }
}

三种情况：

  1. map 值为 0 → 新节点，patch(null, nextChild)
  2. 不在最长递增子序列里 → move
  3. 在序列里 → 跳过（j--）

对比 Vue2 ​

Vue2 的双端 diff 是 O(n)。Vue3 乱序段用最长递增子序列，最坏约 O(n log n)。换算法主要是为了 少动 DOM：多数情况次数接近，递增子序列越长，Vue3 越省。比如下面的例子：

后记 ​

Vue3 编译期还有 Block、hoist、cache 等静态优化。不建议手写 render() 去绕过它们。Block 没开放 API：只收集动态节点，更新时走 fast path 直接 patch 动态节点，不管静态子树。
