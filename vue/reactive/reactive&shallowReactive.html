reactive 与 shallowReactive 的区别 ​

基本概念 ​

  • reactive：深层响应式。对对象做 Proxy 代理后，访问嵌套属性时会递归转成 reactive；属性里的 ref 也会被自动解包。
  • shallowReactive：浅层响应式。只代理根级属性的读写；嵌套对象保持原样，修改嵌套属性不会触发视图更新；根级属性里的 ref 不会自动解包。

两者都只适用于对象类型（含数组、Map、Set 等），不能包基本类型。

对比 ​

维度reactiveshallowReactive
响应式深度深（嵌套对象递归代理）浅（仅根级属性）
嵌套对象修改触发更新不触发更新
根级属性修改触发更新触发更新
根级属性整体替换触发更新触发更新
ref 自动解包会（访问属性时 unwrap）不会
isReactive(根对象)truetrue
isReactive(嵌套对象)truefalse
典型场景常规状态对象大对象、只关心顶层字段、嵌套数据交给子组件
手动触发更新不需要嵌套变更需替换引用或配合 triggerRef 等

示例 ​

reactive：嵌套属性变化会更新 ​

js
import { reactive, isReactive } from 'vue'

const state = reactive({
  count: 0,
  nested: { bar: 1 }
})

state.count++              // ✅ 视图更新
state.nested.bar++         // ✅ 视图更新（nested 已被递归代理）

isReactive(state)          // true
isReactive(state.nested)   // true

shallowReactive：只有根级属性变化才更新 ​

js
import { shallowReactive, isReactive } from 'vue'

const state = shallowReactive({
  count: 0,
  nested: { bar: 1 }
})

state.count++              // ✅ 视图更新
state.nested.bar++         // ❌ 视图不更新（nested 未被代理）

// 若必须改嵌套又要更新视图，替换整个嵌套对象：
state.nested = { bar: 2 }  // ✅ 视图更新

isReactive(state)          // true
isReactive(state.nested)   // false

ref 解包差异 ​

js
import { ref, reactive, shallowReactive } from 'vue'

const count = ref(0)

const deep = reactive({ count })
deep.count++               // ✅ 自动解包，等价于 count.value++

const shallow = shallowReactive({ count })
shallow.count++            // ❌ 改的是 ref 对象本身，不会解包
shallow.count.value++      // ✅ 需手动 .value；且 shallow.count 变更本身不触发根级 set

实际开发里，若根级字段是 ref，优先用 reactive；用 shallowReactive 时要清楚 ref 不会被 unwrap。

大对象场景 ​

状态树很大、渲染只依赖少数顶层字段时，用 shallowReactive 可避免整棵树被 Proxy 包裹，减少内存与依赖追踪开销：

js
import { shallowReactive } from 'vue'

// 第三方返回的复杂树，只关心 list 长度或顶层 id
const store = shallowReactive({
  list: hugeArrayFromServer,
  meta: { version: 1 }
})

store.meta.version++       // ❌ 不更新（meta 未被代理，同 nested.bar++）
store.list[0].name = 'x'   // ❌ 不更新（需整体替换 list 或单独 reactive 子树）

export enum ReactiveFlags { IS_REF IS_REACTIVE }

源码层面 ​

reactive 与 shallowReactive 共用 createReactiveObject，区别在传入的 handlers 和 缓存 Map：

text
reactive(target)        → createReactiveObject(target, false, mutableHandlers,        mutableCollectionHandlers,        reactiveMap)
shallowReactive(target) → createReactiveObject(target, false, shallowReactiveHandlers, shallowCollectionHandlers, shallowReactiveMap)

shallowReactiveHandlers 本质是 new MutableReactiveHandler(true)，即把 _isShallow 设为 true。

get：是否递归 reactive / 解包 ref ​

js
// packages/reactivity/src/baseHandlers.ts（简化）

get(target, key, receiver) {
  const res = Reflect.get(target, key, receiver)

  if (!isReadonly) track(target, TrackOpTypes.GET, key)

  if (isShallow) {
    return res   // 浅模式：直接返回，不 unwrap ref，不递归 reactive
  }

  if (isRef(res)) {
  return isReadonly && isObject(res.value) ? readonly(res.value) : res.value
  }

  if (isObject(res)) {
    return isReadonly ? readonly(res) : reactive(res)
  }

  return res
}

reactive 读嵌套对象时会再走 reactive(res)，所以 state.nested.bar 的修改能被追踪；shallowReactive 在 isShallow 分支直接返回原始嵌套对象，后续修改绕开了 Proxy。

set：浅模式原样写入 ​

js
// MutableReactiveHandler.set（简化）

if (!this._isShallow) {
  oldValue = toRaw(oldValue)
  value = toRaw(value)
  // ... ref 赋值合并逻辑
} else {
  // shallow：对象按原样 set，不做 toRaw
}

const result = Reflect.set(target, key, value, receiver)
// 根级属性变更仍会 trigger

根级 state.nested = newObj 会触发更新，是因为改的是 根 key nested，属于 Proxy 的 set；而 state.nested.bar++ 改的是未代理的 inner 对象，不会经过 shallowReactive 的 set。

与 ref / shallowRef 的对称关系 ​

深响应浅响应
reactiveshallowReactive
refshallowRef
  • reactive ↔ shallowReactive：对象 API，区别在嵌套是否递归代理。
  • ref ↔ shallowRef：ref API，区别在 .value 里的对象是否经 toReactive 深度转换。

解构时：reactive 对象不能直接解构（会丢响应式），需 toRefs；shallowReactive 同样如此。

面试回答要点 ​

  1. 响应式粒度：reactive 深响应，shallowReactive 只追踪根级属性。
  2. 嵌套对象：reactive 访问时递归 reactive()；shallowReactive 嵌套保持原对象，isReactive(nested) 为 false。
  3. ref 解包：仅 reactive 在 get 时自动 unwrap ref；shallowReactive 不会。
  4. 性能：大对象、仅需顶层字段驱动 UI 时，用 shallowReactive 降低代理与依赖收集成本。
  5. 更新嵌套：shallowReactive 下改嵌套需 替换引用（state.nested = { ... }），或对子树单独 reactive。
  6. 源码：共用 createReactiveObject + MutableReactiveHandler，isShallow 控制 get 是否递归代理、set 是否 toRaw。

相关 API ​

  • ReactiveFlags：响应式身份系统

  • shallowRef 与 ref 的区别
  • markRaw：标记对象永不转 Proxy，常与 shallow API 配合
